# Native integer compatibility correction, 2026-10-06

Windows QGIS 3.14.0 was reproduced in its actual 32-bit Python 3.7.0 interpreter, Qt 5.11.2, NumPy 1.21.6, SciPy 1.7.3, scikit-learn 1.0.2, Matplotlib 3.1.3 and pandas 1.0.1. Its NumPy index dtype is int32; explicitly constructed int64 variogram bins fail bincount's safe conversion. Previous Linux 3.14 tests used a 64-bit interpreter and missed this ABI difference.

The same shared binning routine is used by geostatistics, residual regression kriging and Framework. RF training itself succeeds: the error after clicking Fit comes from its subsequent residual semivariogram. Both exact and sampled binning paths now use np.intp, chosen by the running interpreter. Pair ordinals and accumulation counters retain int64. Bin edges, sampling, semivariances, accumulation, seed, fitting, validation and selection policies are unchanged. AST comparisons permit only this storage-type change for the bins; numerical fixtures are never regenerated.

A separate cold-start reproduction found that the shared QGIS3 profile contains cp37/win32 ML wheels. Loading these from Python 3.12/64-bit raises WinError 193. The plugin now tries the current interpreter's working ML stack first, and uses separate local directories per Python/platform ABI. Existing matching legacy wheels remain usable and are not moved or overwritten. Cold-start manual/grid RF with residual binning passed using both the original NumPy 1.18.3 in QGIS 3.14 and NumPy 2.4.2 in QGIS 3.44. Two additional contracts check wheel selection and prevent unnecessary local-package loading; 114 contracts pass in each actual Windows runtime.

Three regression contracts force native int32 bins on 64-bit CI, verify hand-calculated exact results and identical sampled results, and preserve pair ordinals beyond 2^31. Every QGIS runtime also fits RF in both manual and grid modes, then fits and draws its residual semivariogram. The local 3.14 unit suite was adapted to Python 3.7's AST API and the historical Matplotlib backend. It additionally exposed and corrected legacy cloned renderer state, colorbar links, export draw isolation and optional footer bounds. These are display adapters, without statistical changes.

The complete matrix now requires every stable QGIS 3 minor from 3.14 through 3.44 and every stable QGIS 4 minor through the latest official release. The latest patch image is resolved and pinned on each execution. New 4.x stable minors are added automatically. Weekly runs include informational nightly, and pushes/PRs check the minimum, current LTR, 4.0 and latest stable 4.x. Unavailable or failing required versions cannot be reported as passing.

All 18 current stable targets passed 13 functional blocks each in [full CI](https://github.com/ladelgadobe/BestFitInterpolation/actions/runs/37416187749); [fast PR CI](https://github.com/ladelgadobe/BestFitInterpolation/actions/runs/37416190955) also passed. The retired NodeSource repository embedded in official archived 3.30/3.32 test images is disabled only in the disposable Python test image. No QGIS source, version or scientific package is substituted. These workflow changes are in PR 3; GitHub's automatic schedule uses the default branch after integration.

Executed local results and exact environment/source hashes are recorded in integer_compatibility_20261006.json. Windows 3.14 before/after results reproduce the reported traceback and the corrected workflows. CI artifacts linked in PR 3 contain the expanded intermediate-version runs. Offscreen tests use real QGIS/Qt with synthetic layers and an iface double. They do not certify unreleased APIs, every downstream dependency package, native monitor scaling or large datasets.
